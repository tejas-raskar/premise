# Project rules

- Read `CONTEXT.md` before you change a domain term.
- Read `docs/brief.md` before you change the feature scope.
- Keep FalkorDB central to dependency queries and persistent memory.
- Preserve evidence for its original revision.
- Treat a code change as a reason to check evidence, not as proof that a claim is false.
- Use public, synthetic, or owned data.
- Keep the MVP local. Use configured checks in the demo repository.
- Use ASD-STE100 writing rules for human documentation. Keep procedures brief. Use one instruction per sentence.
- Update the relevant document when behavior changes.
- Verify each milestone before you commit it. Keep each commit scoped to that milestone.
- Follow the user's original scope. Review findings do not authorize adjacent features.
